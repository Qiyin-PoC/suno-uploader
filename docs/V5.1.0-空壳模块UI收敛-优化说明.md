# Suno 歌曲上传器 · 空壳模块 UI 收敛优化说明

> 文档版本：V5.1.0
> 撰写：首席产品官（CPO）
> 目标读者：产品 / 运营（决策依据）＋ 前端 / 后端开发（落地清单）
> 适用产物：免安装版 `dist\win-unpacked\Suno歌曲上传器.exe`
> 状态：**已落地**（2026-09-07 已按「档位一：隐藏入口、保留面板」实施并重新打包）

> 落地摘要：侧边栏已收敛为 **上传 / 下载 / 历史** 3 个核心入口；「格式转换 / 音频剪辑 / 伴奏·人声分离」三模块入口从侧边栏移除（底层面板与后端保留，未删除）；未授权时停留首页并提示，不再跳空壳分离页；界面按 ins 风重做（详见《期音科技-ins风UI-设计规范.md》）。

## 一、背景与目标

`Suno歌曲上传器` 的价值主轴是 **「歌曲上传 — 下载 — 历史管理」**。当前侧边栏把 **音频格式转换 / 可视化音频剪辑 / 伴奏·人声分离** 三个附加工具与核心能力并列展示，但它们在免安装版、未获得有效授权（许可证）时的真实表现是：**入口可见、点击即被许可证弹窗拦截**，且依赖后端 Python 环境与（分离用）重型模型。对用户而言，这就是"看到按钮但用不了"的空壳，直接损伤产品的可信度与首屏清晰度。

> **本优化说明的目标**：从 UI 收敛这 3 个空壳入口，让首屏只保留核心价值，同时把"未授权"的引导从"躲进一个空壳工具页"升级为"在首页明确提示 + 置灰"，并对许可锁、跨页联动等关联逻辑给出可落地改造方案。

## 二、现状诊断（定性）

### 2.1 三个模块在代码中的真实状态

| # | 模块 | 面板 ID | UI 入口 / 面板位置 | 交互逻辑 | 门控 | 所需运行时 |
|---|---|---|---|---|---|---|
| 2 | 音频格式转换 | `unlockerPage` | 侧边栏 `index.html:84-87`；面板 `index.html:301` | `app.js` 实现完整 | `requireLicense("音频格式转换/解锁")` | 后端 Python + ffmpeg（解密/开放格式互转） |
| 3 | 可视化音频剪辑 | `editorPage` | 侧边栏 `index.html:88-91`；面板 `index.html:410` | `app.js` 实现完整（波形/选区/导出） | `requireLicense("音频剪辑")` | WebAudio 预览 + ffmpeg 导出 |
| 4 | 伴奏 / 人声分离 | `separationPage` | 侧边栏 `index.html:92-95`；面板 `index.html:523` | `app.js` 实现完整（双 stem 预览/导出） | 免授权（见 2.2） | 后端 Python + 分离模型（需下载 `separationModelSelect`） |

**结论**：三个模块**不是死代码**，`app.js` 均有完整逻辑。它们"看起来是空壳"的根因是**许可证门控 + 运行时依赖**：无有效授权时，点击入口立即触发 `promptLicenseRequired(模块名)`，功能根本走不到。

### 2.2 关键机制：免授权面板与"许可锁"跳转（务必一并处理）

- 免授权面板集合：`setupNavigation()` 中 `freePanels = new Set(["separationPage"])`（`app.js:4454`）——**只有"伴奏/人声分离"页是未授权时可进入的面板**。
- 未授权导航行为（`app.js:4458-4462`）：点击任意**非免费**面板时 → `promptLicenseRequired(...)` → `goToPanel("separationPage")` 被强制带到分离页。

> **这意味着**：当前设计是把「伴奏/人声分离」当作**许可锁定提示页**。用户未授权时，会反复被"藏进"这个空壳工具页——这正是用户感到"空壳"最强烈的触点。

### 2.3 现状问题汇总

1. 入口与核心价值并列，稀释首屏焦点。
2. 空壳入口在未授权时点击即被拦截，体验断裂（明明能看到，却用不了）。
3. 分离页被用作"许可锁页"，让本应轻盈的授权提示变成一个重型工具页，属**产品设计错位**。
4. 跨页联动（转换→进剪辑、剪辑→导出到分离、使用伴奏上传等）都指向这三个页面，收敛时需同步清理，否则出现"点按钮没反应 / 找不到页面"。

## 三、优化方案（推荐：收敛为核心三入口）

### 3.1 首屏信息架构调整

**收敛后侧边栏从 6 项 → 3 项：**

```
1. Suno 歌曲上传      ← 保持
2. Suno 歌曲下载      ← 保持
3. 上传历史           ← 保持
─ 移除：音频格式转换 / 可视化音频剪辑 / 伴奏·人声分离 ─
```

### 3.2 落地改动点清单（附代码坐标）

| 模块 | 文件 | 位置 | 改动 |
|---|---|---|---|
| 入口 | `electron/renderer/index.html` | 84–95 行 | 删除 `unlockerPage` / `editorPage` / `separationPage` 三个 `nav-item` |
| 面板 | `electron/renderer/index.html` | 301 / 410 / 523 行起的 `module-page` | 见 3.3「档位选择」 |
| 导航许可锁 | `electron/renderer/app.js` | `setupNavigation()`（4453–4466） | 调整 `freePanels`；未授权兜底不再跳 `separationPage`（改跳首页，见 3.4） |
| 许可锁跳转 | `electron/renderer/app.js` | `updateLicenseUI()`（4282–4333，尤其 4318–4320） | 未授权不再 `goToPanel("separationPage")`；改为保留当前页 / 回首页并提示 |
| 跨页联动 | `electron/renderer/app.js` | 1114 / 1432 / 4460 / 5795·5799 / 7790 / 8521 | 收敛"转换→进剪辑 / 剪辑→分离 / 使用伴奏上传"等按钮，避免跳转到已下线的面板 |
| 联动按钮 | `electron/renderer/index.html` | `unlockerUseClipBtn` / `dawSeparateBtn` / `clipToUvrBtn` / `useInstrumentalBtn` 等 | 随档位删除或置灰 |
| 主进程/预加载/后端 | `electron/main.js` / `preload.js` / `backend` | 对应 IPC 与命令 | 原则上**保留**（不影响 UI 收敛）；是否清除见 3.5 |

### 3.3 面板如何处置（两种档位，可回滚）

- **档位一：隐藏入口、保留面板（推荐，低风险）**
  仅删 `nav-item`，将三个 `module-page` 用 `hidden` / 样式隐藏。保留 DOM 与事件绑定。优点：彻底收敛首屏，且**不破坏**"转换→剪辑→分离→上传"的既有联动，未来解锁或恢复原样成本最低；未授权时仍可被引导到对应页面（若临时保留引导）。
- **档位二：彻底删除面板与联动（更干净）**
  一并删除三个 `module-page`、对应联动按钮与 `goToPanel("editorPage"|"separationPage")` 全部调用。需完整回归上传 / 下载 / 历史三条主线，确保无残留事件绑定报错。适用于确认这三个能力短期不再回归的场景。

### 3.4 许可锁体验闭环（方案重点）

**改造前**：未授权 → 被困在空壳「分离页」。
**改造后**：未授权 → 停留在 / 回到**上传首页**（`uploadPage`），弹出授权提示；上传、选择文件按钮沿用现有置灰（`app.js:4324-4326` 已对 `startBtn` / `pickBtn` 置灰），导航仅允许进入"下载/历史"或提示授权。

> 原则：授权引导应在**用户想用的地方**（首页 + 置灰 + 提示）完成，而不是把用户藏进一个工具页。

### 3.5 是否顺带瘦身（可选，另行决策）

- `backend` / `python-embed` / 分离模型依赖（UVR 等）当前撑大产物（免安装版 208MB 级）。
- 若三个工具短期不回归，可评估：仅移除 UI 入口（保留后端，打包最小改动）**先发布**；瘦身作为**独立专项**（CI/体积/启动耗时另测），不建议与本次 UI 收敛耦合，避免回归风险。

## 五、验收标准（勾选清单）

- [ ] 首屏侧边栏仅显示 **3 个入口**（上传 / 下载 / 历史）
- [ ] 未授权时停留在首页（或回到首页）并弹出授权提示，不跳转空壳页
- [ ] 未授权时上传 / 选择文件按钮置灰，点击有明确提示
- [ ] 授权后 上传 → 下载 → 历史 全流程正常，无任何依赖已下线面板的报错
- [ ] 控制台无残留事件绑定 / 空引用报错（尤其删除面板后）
- [ ] 若保留后端，转码 / 剪辑导出 / 分离命令在授权态仍可被（非 UI）调用，无冲突
- [ ] 打包产物在免安装版可正常启动，无左上角 `index.html.corrupted_bak` 相关回溯问题
